## 它做什么

把 Android 版的「订阅解析 + 本地代理」搬进 DSH，并额外加了一层**串行反向代理**：

```
DSH 的模型请求 ──► 本地串行反向代理(127.0.0.1:2082) ──► Xray(HTTP 入站 2081)
                                                          ──► 你的机场线路 ──► 上游
```

### 两条硬约束

| 约束 | 实现 |
|---|---|
| **强制并发 1** | 所有请求进同一条串行队列。**必须等上一轮回答彻底写回客户端**，下一个才放行 —— 不是"排队发出"，而是真正串行。 |
| **不允许工具调用** | 请求体的 `tools` / `tool_choice` / `functions` / `function_call` / `parallel_tool_calls` 一律剥掉；响应流里出现的 `tool_calls` 也一并过滤。模型看不到工具，也不会试图调用。 |

两者都有单测覆盖（见下方「验证」）。


## 使用

插件提供两类入口：

### A. 本地管理接口（agent 可直接驱动）

```bash
# 状态
curl -s 127.0.0.1:2083/status

# 拉取并解析订阅
curl -s -X POST 127.0.0.1:2083/subscription -d '{"url":"你的订阅地址"}'

# 查看节点
curl -s 127.0.0.1:2083/nodes

# 连接（按序号或节点名；不传则用第一个）
curl -s -X POST 127.0.0.1:2083/connect -d '{"index":0}'

# 断开
curl -s -X POST 127.0.0.1:2083/disconnect

# 查看实际生成的 Xray 配置与错误日志
curl -s 127.0.0.1:2083/config
```

### B. 让 DSH 的模型走这条线路

把模型 provider 的 **baseURL 指向本地串行代理**：

```yaml
# settings.yaml 示意（按你的 provider 结构填写）
baseURL: http://127.0.0.1:2082/v1
```

转发时序：

```
DSH ──► 127.0.0.1:2082（串行，并发 1）──► Xray ──► 机场 ──► 上游
```

因为并发被强制为 1，DSH 侧的多路请求会自然排队，不会把上游打爆。

## 与 Android 版的差异

| 能力 | Android 版 | 本插件 |
|---|---|---|
| 订阅解析（Clash / base64 / URI） | ✅ | ✅ 完整移植 |
| 协议：vmess / vless(REALITY) / trojan / ss | ✅ | ✅ |
| 本地代理（Xray 子进程） | ✅ | ✅ |
| 接口模式（OpenAI 兼容流式） | ✅ | ✅ 由串行反向代理承担 |
| 诊断（配置 + 日志） | ✅ | ✅ `/config` |
| **网页模式（WebView + DOM 转发）** | ✅ | ❌ **无法移植** —— 依赖 Android WebView，DSH 里没有对应物 |
| **安卓 UI（极光玻璃）** | ✅ | ❌ 无对应物，改为本地管理接口 |

## 已知限制

- **仅 arm64 / x64 Linux**：核心下载脚本按架构选择构建。
- **Xray 不支持 hysteria2 / tuic**：选中这类节点时接口会明确报错。
- **串行是刻意的**：吞吐只有 1，这是需求方明确要求的约束，不是性能缺陷。
- **网页模式未移植**：见上表。
